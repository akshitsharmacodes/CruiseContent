# PRD: Analytics

**Feature:** Post-Performance Analytics
**Users:** All User Tiers
**Stack:** Django 5.2, Celery, React 19 (Recharts/Chart.js)

## Problem Statement
Users currently generate and publish content but have no visibility into how well it performed once live. A centralized analytics dashboard is required to prove the ROI of the content generated by the AI and help users refine their brand voice.
**Success Metrics:**
- Analytics dashboard is visited by >50% of Daily Active Users (DAU).

## User Stories & Acceptance Criteria

1. **Metrics Ingestion (REQ-ANL-001)**
   - *Story:* As the system, I need to periodically fetch engagement data from social platforms.
   - *Acceptance Criteria:* Celery tasks periodically hit platform APIs (Twitter/Meta) to fetch likes, comments, shares, and impressions for each published `SocialPost`.

2. **Dashboard Visualizations (REQ-ANL-002)**
   - *Story:* As a user, I want to see my workspace's performance at a glance.
   - *Acceptance Criteria:* The UI provides a dashboard showing:
     - Total posts published over a time range.
     - Engagement growth charts.
     - Top-performing posts by platform.

3. **Rate-Limit Aware Polling (REQ-ANL-003)**
   - *Story:* As the system, I must not exceed platform API rate limits when pulling data.
   - *Acceptance Criteria:* Analytics pulling is managed by a delayed/throttled Celery queue. Data is pulled asynchronously, not synchronously on user request.

## Scope
- **Ships in v1:** Celery polling tasks for Twitter and Meta platforms, caching of analytics data in Redis/Database, basic UI charts (likes, comments, impressions).
- **Does not ship in v1:** Deep demographic insights, sentiment analysis of comments.

## Data Model Changes
- **[MODIFY]** `SocialPost` - Add fields: `likes_count`, `comments_count`, `shares_count`, `impressions_count`, `last_synced_at`.

## Edge Cases & Failure States
- **Token Expiry:** If a platform token is invalid, the analytics task must gracefully fail and flag the `PlatformAccount` as requiring re-authentication via a UI notification.
- **Stale Data:** If rate limits are hit, the UI should indicate when the data was `last_synced_at` rather than failing entirely.

## Open Questions
- How often should we poll for analytics? (e.g., every 6 hours for the first 48 hours after publishing, then daily for a week, then stop?).
